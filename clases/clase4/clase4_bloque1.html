Bloque 1 – struct Sensor: Agrupar datos del sensor

De variables sueltas a estructura organizada

🔗 Conexión con clases 1-3: En Clase 1 creaste float temp, hum sueltas. En Clase 2 les pusiste alertas con if/switch. En Clase 3 las leíste en bucle con for + millis(). Hoy las agrupamos en un solo tipo.

1. ¿Por qué struct en la estación?

Hasta ahora teníamos variables sueltas (mismo problema que en Clase 1):

// ANTES: variables sueltas (difícil de escalar) - Clase 1 y 3
int pin_dht11 = 2;
float temp_dht11 = 24.5;
float hum_dht11 = 62.0;
int pin_lm35 = A0;
float temp_lm35 = 25.1;
int pin_ldr = A1;
int luz_ldr = 734;
// ... y así para cada sensor

Con struct agrupamos TODO lo que define un sensor (pin + valor + umbrales de Clase 2):

#include 
#include 

// Definición del struct (fuera de main, global)
typedef enum {
    TIPO_DIGITAL = 0,   // DHT11, RTC
    TIPO_ANALOGICO = 1  // LM35, LDR, Water
} TipoSensor;

typedef struct {
    char nombre[20];        // "DHT11", "LM35", "LDR", "LLUVIA"
    uint8_t pin;            // Pin Arduino (0-255)
    TipoSensor tipo;        // DIGITAL o ANALOGICO
    float valor;            // Última lectura
    float umbral_alerta;    // Umbral para alerta
    bool activo;            // Si el sensor está habilitado
    float offset_calibracion; // Corrección (ej: +0.3°C)
} Sensor;

// Ejemplo de inicialización
Sensor dht11 = {
    .nombre = "DHT11_TEMP",
    .pin = 2,
    .tipo = TIPO_DIGITAL,
    .valor = 0.0,
    .umbral_alerta = 30.0,
    .activo = true,
    .offset_calibracion = 0.0
};
💡 typedef enum: Nombres legibles (TIPO_DIGITAL) en vez de números mágicos. uint8_t para pin (1 byte, 0-255).
En Arduino (.ino) es idéntico: struct funciona igual en C y en Arduino C++. Pegá este mismo código en tu sketch de Clase 3 y compila.

1b. Hardware paso a paso — agregamos 3 sensores nuevos

Clase 3 ya tenés DHT11 en D2 cableado. Hoy sumamos LM35 (A0) + LDR (A1) + Agua (A2) sin desarmar lo anterior. Todo a 5V/GND de la protoboard.

Lista de materiales (por grupo)

  • 1x LM35 (TO-92, 3 pines) + 3 cables dupont
  • 1x LDR + 1x resistencia 10kΩ (divisor) + 2 cables
  • 1x Water Sensor (placa) + 3 cables
  • Protoboard + Arduino Uno ya usados en Clase 3

Paso 0 — Alimentación

  1. Conectá 5V Arduino → riel rojo protoboard y GND → riel azul.
  2. Verificá con multímetro: 5V entre rieles.

Paso 1 — LM35 en A0 ( analógico, sin divisor )

LM35 pinCableArduino / Protoboard
VCC (izq, plano al frente)RojoRiel 5V
GND (der)NegroRiel GND
OUT (centro)AmarilloA0

Fórmula: temp = analogRead(A0)*5.0/1023*100. Sin resistencia adicional. Dejá 2-3mm entre pines para no cortocircuitar.

Paso 2 — LDR en A1 (divisor 10k)

ExtremoCableDestino
LDR pata 1Rojo5V
LDR pata 2 + Resistencia 10kAmarilloA1 (nodo común)
Resistencia 10k otro extremoNegroGND

Divisor: A1 = 5V * 10k/(R_ldr+10k). Oscuro → R alta → A1 bajo (<200). Día → R baja → A1 alto (>600). Probá tapando la LDR y mirá `Serial.println(analogRead(A1))`.

Paso 3 — Water Sensor en A2

PlacaCableArduino
VCC (+)Rojo5V
GND (-)NegroGND
S (señal)VerdeA2

Seco ~120, mojado >600. Umbral Clase 2/4 = 500. No sumerjas el conector, solo la zona de pistas.

2. Inicializar array de sensores (configuración centralizada)

Todos los sensores en un solo array: fácil de recorrer con for (Clase 3), fácil de agregar/quitar:

#include 
#include 

#define MAX_SENSORES 6

typedef enum { TIPO_DIGITAL=0, TIPO_ANALOGICO=1 } TipoSensor;

typedef struct {
    char nombre[20];
    uint8_t pin;
    TipoSensor tipo;
    float valor;
    float umbral_alerta;
    float umbral_critico;
    bool activo;
    float offset;
} Sensor;

int main() {
    // Array de sensores: TODA la configuración en UN lugar
    Sensor sensores[MAX_SENSORES] = {
        { .nombre="DHT11_TEMP", .pin=2, .tipo=TIPO_DIGITAL, .valor=0, .umbral_alerta=30, .umbral_critico=35, .activo=true, .offset=0 },
        { .nombre="DHT11_HUM",  .pin=2, .tipo=TIPO_DIGITAL, .valor=0, .umbral_alerta=80, .umbral_critico=90, .activo=true, .offset=0 },
        { .nombre="LM35",       .pin=A0, .tipo=TIPO_ANALOGICO, .valor=0, .umbral_alerta=30, .umbral_critico=35, .activo=true, .offset=0.3 },
        { .nombre="LDR",        .pin=A1, .tipo=TIPO_ANALOGICO, .valor=0, .umbral_alerta=200, .umbral_critico=100, .activo=true, .offset=0 },
        { .nombre="LLUVIA",     .pin=A2, .tipo=TIPO_ANALOGICO, .valor=0, .umbral_alerta=500, .umbral_critico=800, .activo=true, .offset=0 },
        { .nombre="RTC",        .pin=5, .tipo=TIPO_DIGITAL, .valor=0, .umbral_alerta=0, .umbral_critico=0, .activo=true, .offset=0 }
    };

    int total = 6;

    printf("=== ESTACIÓN METEOROLÓGICA - SENSORES CONFIGURADOS ===\n\n");
    for (int i = 0; i < total; i++) {
        if (sensores[i].activo) {
            printf("%2d. %-12s | Pin %2d | %s | Alerta: %.1f | Offset: %.2f\n",
                   i+1, sensores[i].nombre, sensores[i].pin,
                   sensores[i].tipo == TIPO_DIGITAL ? "DIGITAL " : "ANALOGICO",
                   sensores[i].umbral_alerta, sensores[i].offset);
        }
    }

    return 0;
}
Salida:

 1. DHT11_TEMP   | Pin  2 | DIGITAL   | Alerta: 30.0 | Offset: 0.00

 3. LM35         | Pin 14 | ANALOGICO | Alerta: 30.0 | Offset: 0.30

3. Funciones que operan sobre Sensor (paso por VALOR - copia)

Si pasamos el struct por valor, la función recibe una copia. Los cambios NO afectan el original:

#include 

typedef struct {
    char nombre[20];
    float valor;
    float offset;
} Sensor;

// Paso por VALOR: recibe COPIA
void aplicar_offset_valor(Sensor s) {
    s.valor += s.offset;  // Modifica la copia
    printf("  Dentro: %s = %.2f (offset aplicado)\n", s.nombre, s.valor);
}

int main() {
    Sensor lm35 = { .nombre="LM35", .valor=25.0, .offset=0.3 };

    printf("Antes: %s = %.1f\n", lm35.nombre, lm35.valor);  // 25.0
    aplicar_offset_valor(lm35);                              // Copia
    printf("Después: %s = %.1f\n", lm35.valor);              // 25.0 ← NO CAMBIÓ!

    return 0;
}
⚠️ Problema: Pasar struct por valor copia TODOS los bytes (lento, gasta stack). En embebidos con structs grandes = malo. Y no modifica el original.
🧪 Práctica de laboratorio (20 min): Cargá el array de 6 sensores en tu Arduino (sin leer aún). Imprimí por Serial 9600 la tabla de configuración como en el ejemplo. Verificá que compila en Arduino IDE (mismo código que en gcc).

Resumen Bloque 1

  • struct Sensor agrupa: nombre, pin, tipo, valor, umbrales, offset, activo (junta variables de Clase 1 + umbrales de Clase 2)
  • typedef enum para tipos legibles (TIPO_DIGITAL, TIPO_ANALOGICO)
  • Array Sensor sensores[] = configuración centralizada, se recorre con for de Clase 3
  • Paso por valor = copia, no modifica original, gasta memoria (2KB RAM en Uno)
  • Siguiente: Punteros → paso por referencia, modifica original, eficiente. Lo usaremos en leer_sensor(&s) real con DHT11.
